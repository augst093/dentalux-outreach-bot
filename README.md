# DentaLux: бот одобрения исходящих сообщений

Telegram-бот для владельца DentaLux. Он готовит персональные первые сообщения стоматологическим клиникам Ташкента, показывает их вам в Telegram, и только после вашего «Да» выдаёт готовый текст. Отправляете сообщение вы сами.

## Что бот делает и чего не делает

- **Не отправляет** сообщения клиникам. Вообще. «Отправить» в карточке означает «одобрить и показать текст». Бот пишет только вам.
- **Не использует** личные аккаунты (Telegram user-аккаунты, Instagram), не хранит сессии, не делает рассылок и не обходит защиты сайтов.
- **Не принимает** платежи. Оплату вы записываете вручную командой `предоплата`.
- **Не хранит** данные пациентов. Только публичные данные клиник: название, направление, публичный контакт, заметка.
- Работает только через официальный Telegram Bot API. Пишет только владельцу (ADMIN_USER_ID). Всем остальным отвечает одной фразой без списка функций.

## Команды для телефона

Все команды пишутся в чат с ботом. Бот отвечает только вам.

| Команда | Что делает |
|---|---|
| `список кому пишешь` | Показывает до 5 черновиков в очереди, с кнопками |
| `Да` | Одобряет черновик, который сейчас «в фокусе» (первая карточка из списка) |
| `Нет` | Пропускает этот черновик |
| `Переделай: <пожелание>` | Переписывает текущий черновик. Например: `Переделай: короче`. Для узбекского: `Переделай: на узбекском` |
| `ответ <клиника>: <текст>` | Записывает ответ клиники, готовит черновик ответа, ждёт вашего «Да» |
| `отправлено <клиника>` | Вы отправили одобренный текст. Статус меняется на «отправлено» |
| `статус` | Сводка: сколько отправлено, сколько ответов, переговоры, предоплаты |
| `добавить клинику` | Пошагово: название, направление, публичный контакт, заметка |
| `предоплата <клиника>: <сумма>` | Записывает предоплату, которую вы получили вручную (например, `250`) |
| `запуск <клиника>` или `запуск <клиника>: <сумма>` | Запуск демо-версии. Без суммы записывается остаток 200 $ |
| `подписка <клиника>: <сумма>` | Записывает платёж подписки (50 $/мес) |
| `переговоры <клиника>` | Отмечает клинику как «на переговорах» |
| `opt_out <клиника>` | Клиника попросила не писать. Новые сообщения блокируются |
| `помощь` | Список команд |

Правила, которые бот соблюдает сам:

- **Одно «Да» = одно сообщение.** Одобрение не распространяется на другие.
- **Лимит:** не больше `DAILY_SEND_LIMIT` одобрений в день (по умолчанию 10, день считается по Ташкенту).
- **Пауза:** между одобрениями не меньше `SEND_PAUSE_SECONDS` (по умолчанию 180 секунд).
- **Публичный контакт обязателен.** Без него одобрение заблокировано.
- **Opt-out:** если ответ клиники просит не писать (например, «не пишите», «отпишите», «stop», «yozmang»), бот сам ставит статус `opt_out`, закрывает открытые черновики и сообщает вам. Правило намеренно широкое: лучше лишний раз заблокировать, чем написать после отказа.
- Цены в первом сообщении не упоминаются. В ответах допускаются только условия из брифа: 250 $, 200 $, 50 $.

## Как устроено

```
app/main.py              точка входа: HTTP (/health, webhook), polling только для локальных тестов
app/config.py            настройки из переменных окружения
app/bot/handlers.py      Telegram: проверка владельца, мастер «добавить клинику», кнопки
app/bot/parsing.py       разбор команд (чистые функции)
app/services/operator.py логика команд владельца (без Telegram, тестируется отдельно)
app/services/tracker.py  статусы клиник, черновики, одобрения, ответы, платежи, события
app/services/drafts.py   Claude API с проверкой ответа, шаблоны как запасной вариант
app/services/limits.py   дневной лимит и пауза
app/db/models.py         таблицы clinics, messages, events, payments
app/db/migrations/       миграции Alembic
tests/                   pytest
```

Статусы клиники: `new` → `ready` → `approved` → `sent` → `replied` → `negotiating` → `prepaid` → `launched`. Также `skipped` и `opt_out`. `opt_out` доступен из любого живого статуса и необратим. Недопустимые переходы отклоняются, каждое изменение пишется в `events`.

Claude: модель `claude-sonnet-5-5`. Если ключа нет, API падает или ответ модели не проходит проверку (длина, восклицательные знаки, капс, один вопрос в конце, упоминание DentaLux и ассистента, запрещённые цены и обещания), бот берёт шаблон и пишет вам, почему.

## Локальный запуск и тесты

Нужен Python 3.11 или новее.

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
pytest
```

Миграции на локальной SQLite:

```bash
cp .env.example .env               # и заполните BOT_TOKEN, ADMIN_USER_ID и ALLOW_POLLING=1
alembic upgrade head
python -m app.main                 # локально: long polling, потому что PUBLIC_WEBHOOK_URL пуст
```

`ALLOW_POLLING=1` нужен только локально. На Railway его не задавайте: без `PUBLIC_WEBHOOK_URL` сервис не запустится, и это правильно.

Для локального запуска создайте **тестового** бота в @BotFather (отдельный от рабочего). Токен кладите только в `.env`, который в `.gitignore`.

## Деплой на Railway (пошагово)

### Шаг 1. Создайте бота одобрения в @BotFather

1. Откройте Telegram, найдите **@BotFather**, нажмите Start.
2. Отправьте `/newbot`.
3. Введите имя (например, `DentaLux Approval`) и username, который заканчивается на `bot` (например, `dentalux_approval_bot`).
4. BotFather пришлёт токен вида `123456789:AAH...`. **Скопируйте его и никому не отправляйте в чат.** Этот токен понадобится в шаге 4.

Это бот одобрения, а не клинический бот DentaLux. Клиникам он ничего не отправляет.

### Шаг 2. Узнайте свой ADMIN_USER_ID

1. В Telegram найдите **@userinfobot** и нажмите Start.
2. Он пришлёт ваш `Id`, это число вроде `123456789`. Запишите его.

### Шаг 3. Создайте проект на Railway

1. Зайдите на https://railway.com и войдите.
2. Код лежит в репозитории GitHub (этот проект целиком, без файла `.env`). Если деплоите со своего аккаунта, сделайте fork этого репозитория и синхронизируйте его с основным (**Sync fork**), чтобы подтянуть последние изменения. Railway подключается именно к вашему fork.
3. В Railway нажмите **New Project → Deploy from GitHub repo** и выберите fork репозитория.
4. Railway найдёт `Dockerfile` и `railway.json`. Первый деплой может упасть, пока не заданы переменные. Это нормально.
5. В том же проекте нажмите **+ New → Database → Add PostgreSQL**. Появится сервис `Postgres`.

### Шаг 4. Задайте переменные в Railway

Откройте сервис приложения (не базу), вкладка **Variables**, и добавьте:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен из @BotFather (шаг 1) |
| `ADMIN_USER_ID` | ваш Id из @userinfobot (шаг 2) |
| `DATABASE_URL` | `${{Postgres.DATABASE_URL}}`. Скопируйте в точности, Railway подставит адрес базы сам |
| `WEBHOOK_SECRET` | длинная случайная строка, см. ниже |
| `ANTHROPIC_API_KEY` | необязательно. Ключ Claude. Без него работают шаблоны |
| `DAILY_SEND_LIMIT` | необязательно. По умолчанию `10` |
| `SEND_PAUSE_SECONDS` | необязательно. По умолчанию `180` |
| `PUBLIC_WEBHOOK_URL` | добавьте после шага 5, см. ниже |

**WEBHOOK_SECRET** придумайте сами: 32+ символов из букв, цифр, `_` и `-`. Самый простой способ: сгенерировать его на своём компьютере командой `python -c "import secrets; print(secrets.token_urlsafe(32))"` и вставить результат в Railway. Не отправляйте его в чат.

**Важно:** значения вводите только сами в интерфейсе Railway. Не присылайте токены и ключи в чат с ботом или с кем-либо ещё.

### Шаг 5. Получите публичный адрес и включите webhook

1. Откройте сервис приложения → **Settings → Networking → Generate Domain**. Railway выдаст адрес вида `https://dentalux-outreach-production.up.railway.app`.
2. Вернитесь в **Variables** и задайте `PUBLIC_WEBHOOK_URL` = этот адрес **без слэша в конце**.
3. Railway перезапустит сервис. Проверьте здоровье: откройте в браузере `https://<ваш-адрес>/health`. Должно появиться `{"status": "ok", "database": "ok"}`.

Миграции базы выполняются автоматически перед каждым стартом (`alembic upgrade head`), отдельно их запускать не нужно.

Если `/health` показывает `"database": "down"`, проверьте, что `DATABASE_URL` задан как `${{Postgres.DATABASE_URL}}`.

### Шаг 6. Проверьте бота

1. Откройте чат с вашим ботом одобрения в Telegram и отправьте `/start`. Должна появиться справка.
2. Отправьте `статус`. Должна появиться сводка с нулями.
3. Попросите знакомого написать боту. Ответ: «Этот бот работает только для владельца DentaLux».

### Шаг 7. Первое добавление клиник

1. Отправьте `добавить клинику`.
2. Введите название, направление (например, `импланты`), публичный контакт (телефон, `@username` или ссылку `t.me/...`), заметку (что видно публично, или `-`).
3. Бот сделает черновик и покажет карточку с кнопками.
4. Отправьте `список кому пишешь`, прочитайте текст. «Отправить» одобряет текст и даёт контакт. После этого отправьте сообщение клинике сами и напишите `отправлено <название клиники>`.

Не больше 10 одобрений в день. Между одобрениями минимум 3 минуты.

## Решения, которые приняты без вас

- **aiogram 3** (а не python-telegram-bot): нативный webhook с проверкой secret_token, FSM для мастера добавления, активная поддержка.
- **SQLAlchemy 2.0 async + asyncpg** (PostgreSQL) и **aiosqlite** (локальные тесты). Миграции Alembic.
- **Одобрение = единица лимита.** Лимит считает одобрения (нажатие «Да»), потому что бот не отправляет сам. Одобрение без отправки тоже занимает слот, это осознанно.
- **«Да» без номера** относится к карточке в фокусе: первой из последнего `список кому пишешь`, либо к той, которую вы только что создали или переделали. Для остальных используйте кнопки.
- **Ответ клиники** записывается как событие и хранится в `events` вместе с текстом, это аудит. В логах текста нет.
- **Мастер добавления клиники** хранит состояние в памяти. Если сервис перезапустился посреди мастера, начните заново.
- **Запуск без суммы** записывает 200 $ (остаток из брифа). Укажите сумму явно, если она другая.
- **День для лимита** считается по `TIMEZONE` (по умолчанию `Asia/Tashkent`).
- **Команда `отправлено`** добавлена, потому что статус «отправлено» иначе невозможно поставить. Команды `переговоры`, `запуск`, `подписка` тоже добавлены, по той же причине.
- **Пакетное одобрение не реализовано.** Бриф разрешает его только по явной просьбе владельца в этом же чате. Пока каждое сообщение одобряется отдельно.

## Что владелец делает сам

1. Создаёт бота в @BotFather и вводит токен в Railway.
2. Узнаёт свой ADMIN_USER_ID через @userinfobot и вводит его в Railway.
3. Создаёт проект, PostgreSQL и домен на Railway.
4. Задаёт `WEBHOOK_SECRET`, `PUBLIC_WEBHOOK_URL` и (по желанию) `ANTHROPIC_API_KEY`.
5. Добавляет клиники сам: проверяет публичные данные в открытых источниках вручную.
6. **Сам отправляет** каждое одобренное сообщение из своего аккаунта или по публичному контакту клиники, и потом пишет `отправлено`.
7. Записывает предоплаты, запуски и подписки вручную.
8. Решает, менять ли цены и условия. Бот их не меняет.

## Что нельзя автоматизировать без риска

- **Личные аккаунты** (Telegram user-аккаунты через Telethon/Pyrogram, Instagram-сессии, скрипты личных сообщений). Нарушают правила платформ и ведут к блокировке аккаунтов. Бот этого не делает.
- **Холодные рассылки** по списку контактов без одобрения каждого сообщения. Это спам и риск блокировки. Бот отправляет текст только после вашего «Да», а отправку делаете вы.
- **Сбор контактов обходом защит** (скрейпинг 2GIS, Яндекс Карт и т. п.). Клиники добавляете вы вручную или присылаете список, который бот разбирает сам.
- **Обещания выручки, гарантии и цены вне брифа.** Бот их не пишет, проверка на это есть в `app/services/drafts.py`.

## Безопасность

- Токены, ключи и `WEBHOOK_SECRET` только в переменных окружения Railway. В коде, git и логах их нет.
- `.env` в `.gitignore` и `.dockerignore`. `.env.example` содержит только имена переменных.
- Webhook принимает запросы только с правильным `X-Telegram-Bot-Api-Secret-Token`.
- Каждое обновление проверяется по `ADMIN_USER_ID` до того, как что-либо читается или меняется.
- Контейнер запускается не от root.
- Логи содержат статусы и id, но не текст сообщений клиник и не токены.

## Что проверено, а что нет

- Тесты (`pytest`) покрывают права доступа, переходы статусов, лимит в день, паузу, opt-out, генерацию без ключа Claude, разбор команд, сценарии владельца через настоящий диспетчер aiogram с фейковым Telegram, миграции Alembic и `/health`.
- **Не проверено здесь:** реальная работа webhook на Railway и разговор с живым Telegram. Тестовый запуск с выдуманным токеном доказывает только, что сервис стартует и HTTP-сервер поднимается.
